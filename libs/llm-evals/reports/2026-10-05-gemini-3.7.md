# Gemini 3.7 Flash evaluation — 2026-10-05

## Setup

- Model under test: `apologist:google/gemini/3.7-flash`, using the production Apologist URL and API key from Doppler `journeys/prd`.
- Judge: the suite's default OpenRouter model, using `OPENROUTER_API_KEY` from Doppler `journeys/stg`.
- Prompt: `apologist-world-cup-chat@development`, compiled with `translation: 'ESV'`. At the start of the run, the `development` and `production` labels both resolved to Langfuse version 9 and compiled to identical text.
- Each run used a live `generateText` call followed by a separate LLM judge call. Nx caching was disabled for the eval target.

No credential values are stored in this report. The local `libs/llm-evals/.env` is ignored by Git and has file mode `0600`.

Premarital sex, divorce after infidelity, Trinity, money worry, and all four scope/off-topic scenarios passed in both full runs. Problem of evil passed in the first run, then returned no text in the second. The per-cell reports in `results/` contain the latest full-run outputs and judge reasons; `results/summary.md` combines those with older results from other models and dates.

Across seven harness attempts at the resurrection scenario (the two full runs plus five focused reruns), two passed, three produced substantive answers below the rubric threshold, and two produced no text. The empty responses were originally scored as failed answers by the judge; the harness now reports them as generation errors instead. A separate raw Apologist response probe captured HTTP 200 with `finish_reason: "content-filter"`, empty content, and zero completion tokens for the same query and full system prompt. Another raw full-prompt probe returned a normal answer. This filtering is intermittent in the observed sample.

The judge also made at least one questionable claim: in the second full run it penalized the resurrection answer for markdown headings, although the saved output has bullet points and bold labels, with no headings. Review the saved output as well as the numeric score before using that failure as evidence of model quality. The empty responses and the repeated speaking-in-tongues miss do not depend on that disputed judgment.

## Recommendation

**Do not update production to `google/gemini/3.7-flash` yet.** The ID is accepted by Apologist, but a successful HTTP status did not reliably produce a response in the pastoral scenarios. Investigate the gateway's `content-filter` result and rerun the key pastoral and doctrinal scenarios until they are stable. Then review any remaining rubric failures manually, especially the resurrection opener. This suite uses a single-turn `generateText` call; the Journeys chat route streams responses, so a final production decision should also include a streaming-path check.
